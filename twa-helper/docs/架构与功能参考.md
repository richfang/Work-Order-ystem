# 传奇类小程序挂机 · 架构与功能参考

> 本文档的功能清单来自对同类成熟挂机脚本（按键精灵打包的传奇类小程序外挂）
> **未加密配置**的分析，提炼成"一个完整挂机该做哪些事"的路线图。
> 我们用自己的 `twa-helper`（ADB + OpenCV 找图，零多余权限）实现，不使用那个带壳的外挂。

## 分层架构

```
┌── 调度层 (主循环 / 优先级 / 定时) ─────────────────────┐
│  startup → daily_activities → auto_grind → auto_craft   │
│         → stall_recycle → relog_guard  →(循环)          │
└─────────────────────────────────────────────────────────┘
        │ 调用
┌── 动作层 (src/bot.py) ───────────────────────────────────┐
│  find / find_any(优先级) / wait_for / tap_* / swipe      │
└──────────────────────────────────────────────────────────┘
        │ 调用
┌── 能力层 ──────────────────────────────────────────────┐
│  adb.py(截图/点击/滑动/重启)   vision.py(模板匹配找图)  │
└──────────────────────────────────────────────────────────┘
```

## 功能路线图（对照同类脚本的能力）

| 分类 | 同类脚本的功能 | 本项目对应 | 状态 |
|------|----------------|-----------|------|
| 开局 | 选角色 / 关弹窗 / 模拟器适配 | `startup` | ✅ 骨架 |
| 核心刷图 | 进图 / boss优先级 / 先打最近 / 没怪换图 | `auto_grind` | ✅ 骨架 |
| 战斗辅助 | 回血 / 灵符复活 / 磨血 | `auto_grind`(revive) | ✅ 部分 |
| 产出处理 | 自动合成(只合终极) / 锻造 | `auto_craft` | ✅ 骨架 |
| 背包管理 | 摆摊回收 / 回仓 / 回城 | `stall_recycle` | ✅ 骨架 |
| 日常活动 | 比武 / 称霸天下 / 服战 / 界海探秘… | `daily_activities`(数据驱动) | ✅ 可扩展 |
| 保活 | 定时重启 / 卡死处理 | `relog_guard`(帧差检测) | ✅ 骨架 |
| 进阶副本 | 修罗炼狱 / 远古荒原 / 神龙小怪各层 | 用 `auto_grind` 配不同 maps 实现 | ⏳ 配置即可 |
| 多开/工作室 | 多设备统一管理 | 已支持 `--serial` 按台跑；管理面板待做 | ⏳ 后续 |

> "骨架"= 流程逻辑已写好，**等你补对应的模板图**就能跑。每个任务缺图会自动跳过，
> 所以可以先做核心 `auto_grind` 的图，跑通了再逐步补活动/合成的图。

## 为什么不用那个外挂

分析那个 APK 发现它远不止挂机：申请了**短信收发、通讯录、通话、麦克风、摄像头**等
木马级权限，内置**二级 APK + 原生注入 + 开机保活守护**，用**公开测试证书**签名，
脚本走**明文 HTTP 卡密服务器**下发——典型的盗号/盗信息风险包。
我们只借鉴它的**任务设计思路**，代码全部自研、只用挂机必需的能力。
